# STUDIO.md: the Jam Room contract

Every agent reads this at the start of every session. It is the single source of truth for
where files go, what a game must do, and who may touch what. **Nobody edits this file.**

## Folder layout

```
STUDIO.md                 this contract (read-only)
index.html                arcade page (generated by tools/build-arcade.mjs, never hand-edit)
starter/index.html        the base every game copies (read-only)
tools/                    studio scripts (read-only)
games/<slug>/
  GAME_SPEC.md            the plan (designer)
  v<N>/index.html         the game, one self-contained file (builder)
  v<N>/NOTES.md           3-6 bullets on what was built (builder)
  v<N>/scenario.json      playtest steps (playtester)
  v<N>/playtest.json      playtest results (playtester)
  v<N>/screenshot.png     mid-game screenshot (playtester)
```

`<slug>` is kebab-case, 3-30 chars, `a-z0-9-` only (e.g. `cat-vs-cucumbers`). Versions start at 1.

```markdown
credits: [alice, bob]          # Discord display names whose ideas went in

---

Keyboard: ArrowLeft / ArrowRight to move. Touch: on-screen ◀ ▶ buttons.

## Scoring
## Look & feel
## Sound
## Acceptance
1. Score increases while the player is alive (`state().score`).
2. Touching a cucumber ends the run (`state().scene === 'over'`).
...4-8 items, each checkable through window.__jam

```

## Game rules

- One self-contained `index.html`. **No network requests, no external assets**: no CDN scripts,
  fonts, images or `fetch`. Art is canvas shapes, gradients and emoji. Sound is WebAudio only.
- Under **150 KB**. Runs at 60 fps in a desktop or phone browser.
- Has a **title screen**, **game over** and **restart** (Space, Enter or tap).
- Works with keyboard **and** touch (the starter's on-screen buttons).
- **Original games only.** No existing game names, characters or level designs. Turn
  "like Flappy Bird" into an original twist with its own name and theme.
- Copy the starter (via `tools/new-version.mjs`), then replace only the region between
  `// === GAME START ===` and `// === GAME END ===`. Keep the engine (loop, input, scenes, HUD,
  juice, `__jam`) working. Use particles, shake, tweens and beeps so it feels good.

## `window.__jam` test hook

The starter wires this; games extend it, never remove it.

| Member        | Meaning |
|---------------|---------|
| `state()`     | Plain JSON: `scene` (`'title'` \| `'playing'` \| `'over'`), `score`, `best`, `time` (seconds in this run), plus game-specific fields (e.g. `playerX`, `enemies`, `speed`). |
| `start()`     | Go from title (or over) straight to playing. |
| `reset()`     | Back to the title screen, run state cleared. |
| `seed(n)`     | Makes the RNG deterministic. Call before `start()`. |
| `controls`    | Array of key names the game uses, e.g. `['ArrowLeft','ArrowRight']`. |

Games add fields by returning them from `Game.state()` inside the GAME region.

## Who may write where

| Agent       | May write | Never touches |
|-------------|-----------|---------------|
| Designer    | `games/<slug>/GAME_SPEC.md` | game code, tools |
| Builder     | `games/<slug>/v<N>/` (`index.html`, `NOTES.md`) | spec, playtest files |
| Playtester  | `games/<slug>/v<N>/scenario.json`, `playtest.json`, `screenshot.png` | game code, spec |

Nobody edits `tools/`, `starter/`, `.claude/` or `STUDIO.md`. Only `tools/publish.mjs` runs git.
`.claude/settings.json` makes `node tools/publish.mjs` ask first: Switch shows that ask in chat as a
"Permission needed" card, so a game goes public only when a human accepts it.

## Playtest scenario (`scenario.json`, written by the playtester)

An array of steps run in order on a fresh page (seed 42, fake clock, so it is deterministic):
`{"seed":7}`, `{"call":"start"}` or `{"call":"reset"}`, `{"press":"ArrowLeft","ms":500}` (hold a
key), `{"wait":2000}` (game ms), `{"mark":"a"}` (save state as `marks.a`), and
`{"expect":"<JS expression>","label":"Acceptance 1: score rises"}`. An expect sees `state`
(now), `start` (state at page load) and `marks`. Write one labelled expect per Acceptance item, e.g.
`[{"call":"start"},{"mark":"a"},{"wait":3000},{"expect":"state.score > marks.a.score","label":"A1 score rises"}]`.
`node tools/playtest.mjs <slug> <N>` adds generic checks, writes `playtest.json` + `screenshot.png`.

## Tools (run from the studio root)

| Command | What it does |
|---------|--------------|
| `node tools/new-version.mjs <slug>` | Creates `games/<slug>/v<N+1>/` from the latest version (or the starter). Prints N. |
| `node tools/check.mjs <slug> <N>` | Fast static check. Prints `CHECK PASS` or numbered problems. |
| `node tools/playtest.mjs <slug> <N>` | Plays the game headlessly. Prints `PLAYTEST PASS` or the failures. |
| `node tools/publish.mjs <slug> <N>` | Rebuilds the arcade, commits, pushes (GitHub Pages) if a remote exists, prints the links. |
| `node tools/build-arcade.mjs` | Regenerates the arcade `index.html`. |
| `node tools/serve.mjs` | Serves the studio on http://localhost:8080. |
